Five short slides to set up the workshop: why we work this way, why the output is Reveal.js, what the process looks like, how a Claude Project holds it together, and how tags in the outline control the slides. This deck uses the same Field Guide style the workshop template ships with.

1Why not just ask Claude for the deck?

  • Diving in means revising the deck itself, and every change has Claude re-read and rewrite a heavy file.
  • In a long chat, everything earlier is resent with each new message, so a big deck makes every later turn cost more.
  • A text outline is a fraction of the size: cheap to revise, cheap to re-read, easy for you to review.
Remember

Get the content right in text first. Generate the deck once.

Ask how many people have asked for a deck, then spent the next hour asking for changes to it. Each of those changes paid for the whole deck again. The chart is a shape, not a measurement: the point is that rebuilds add up while outline edits stay small.

2Why Reveal.js?

  • Two dimensions. Walk across for the overview; go down for detail. One deck serves the live session and self-guided reading afterward.
  • It's just HTML. Diagrams, charts, code, click-to-reveal answers, links, and speaker notes in one file that opens in any browser.
  • Text all the way down. Claude edits one slide's HTML instead of regenerating a binary file, and every change shows up cleanly in git.
Tip

Press S in any Reveal.js deck to open the speaker view with notes and a timer.

Sources: Reveal.js: vertical slides · Speaker view
The 2D grid is the key idea: the top row is a complete talk on its own, and the columns below hold what you'd cover if there's time, or what people read later on the hosted deck. Because the deck is text, a fix to one slide is a small, targeted edit.

3The process

Phase 1Many cheap revisions of a numbered, tagged Markdown outline.
The gateA recorded approval in DECISIONS.md, not a casual "show me a slide".
Phase 2One build from the approved outline, then targeted fixes and checks.
This is the same flow as the repo README. Stress the gate: it's what stops Claude from jumping to slides early, and it's a line in a file, so every chat can see it.

4A Claude Project as the workspace

  • Chats don't share history; files do. Claude writes OUTLINE.md and DECISIONS.md at checkpoints, so a fresh chat picks up where the last one stopped.
  • The instructions are the same for every talk. Only BRIEF.md changes.
Source: Claude Help Center: Projects
Fresh chats are a feature: a review chat isn't anchored to the drafting chat's choices, and short chats cost less. The files carry the state between them.
